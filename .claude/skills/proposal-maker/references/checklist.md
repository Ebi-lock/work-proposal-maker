# 提出前チェックリスト

生成前（Step 4 の骨子確認）と生成後に、該当するリストを確認する。
結果は「OK／要対応」で表にしてユーザーに見せる。要対応の項目は、直し方まで具体的に伝える。
自分で直せるもの（表記ゆれ、数字の不一致など）は直してから報告する。事実の確認が必要なものは質問する。

## 共通（企画書・提案書すべて）
- [ ] 各スライドの見出し（message）が結論の1文になっている（項目名だけになっていない）
- [ ] 見出しだけを順に読んで、話が通じる
- [ ] 同じ数字がスライド間で一致している（サマリー・効果・費用など）
- [ ] 合計・ROI・回収期間を計算し直して合っている
- [ ] 数字に根拠（ユーザーの情報、出典）がある。【要確認】が残っていない、または残っていることを伝えた
- [ ] リスクにすべて対策が付いている
- [ ] 最後に、次のアクションと期限がある
- [ ] 色は3色、フォントはメイリオのみ（スクリプトが守る）

## 社外向け提案書（クライアント営業）
**相手目線**
- [ ] 課題を相手の言葉と数字で書いている（ヒアリング内容が反映されている）
- [ ] 効果の主語が相手になっている（「貴社の集計作業が〜」）。自社の売り込みになっていない
- [ ] 解決策が、すべての課題に対応している

**表記・マナー**
- [ ] 宛名が正しい（会社宛は「御中」、個人宛は「様」。併用しない）。社名を正式名称で書いている（株式会社の前後など）
- [ ] 資料の中では「貴社」を使う（「御社」は話し言葉）
- [ ] 敬語が丁寧すぎない、くだけすぎない（「ご提案」「〜いたします」）

**費用・条件**
- [ ] 税別か税込かを書いている
- [ ] 初期費用と月額（年額）を分けて書いている
- [ ] 見積の有効期限、費用に含まれる範囲と含まれない範囲を書いている

**信頼性**
- [ ] 実績・事例の数字が事実で、新しい
- [ ] 事例に他社名を出す場合、掲載の許可がある（なければ「物流A社」のように伏せる）
- [ ] 競合を悪く言っていない（比較は事実だけ）

**情報管理**
- [ ] 自社の内部情報（原価、利益率、社内の事情、他の顧客の情報）が入っていない
- [ ] 他社向けの資料を流用した跡（別の社名、別の数字）が残っていない

**行動の促し**
- [ ] ネクストアクションが、相手が動きやすい小さな一歩になっている（打ち合わせ、トライアル、資料請求など）
- [ ] 担当者が社内で回しやすい（先方の上司が見ても分かる概要スライドがある）

## 社内向け提案書（稟議・改善提案）
**結論と判断材料**
- [ ] 1枚目（概要）で「何を・いくらで承認してほしいか」が分かる
- [ ] 効果を金額に換算している（工数は「時間×人数×時給」）
- [ ] 投資回収期間、またはROIを示している
- [ ] 代替案（現状維持を含む）と比べて、この案を選ぶ理由を示している
- [ ] 何もしなかった場合の損失を示している

**社内ルール**
- [ ] 金額が提出先の決裁権限の範囲内か確認した（超える場合は宛先や決裁ルートを見直す）
- [ ] 計上する予算の費目を確認した（経理・予算担当と合意済みか）
- [ ] 稟議書の様式が社内で決まっている場合、その様式に必要な項目を満たしている

**実行可能性**
- [ ] 責任者を実名で書いている
- [ ] 関連部署への影響（工数、既存業務への影響）を書き、合意状況を示している
- [ ] スケジュールが繁忙期や決算期とぶつかっていない

**根拠**
- [ ] 現状の数字が社内データ（調査日・対象）に基づいている
- [ ] 試算の前提（時給、件数、期間）を書いている

**表記**
- [ ] 「貴社」「御社」などの社外向けの表現が残っていない
- [ ] 社外秘の表記を付けている（必要な場合）
- [ ] 社内の略語や専門用語は、決裁者に伝わるものだけにしている

## 企画書（商品企画）
- [ ] 背景 → 3C・SWOT → As-Is/To-Be → 課題・ゴールが論理的につながっている
- [ ] ゴールがSMART（具体的・測れる・達成できる・目的に関係する・期限がある）
- [ ] ターゲットの困りごとと、提供価値が対応している
- [ ] 価格の根拠（原価、競合価格）がある
- [ ] 6W2Hの8項目がすべて埋まっている
