# 提案書：構成とセクション別ヒアリングガイド

提案書は「相手の課題 → 解決策 → 相手が得るもの → 実行計画 → 次の一歩」で説得する文書。
企画書との違いは、**主役が読み手（相手）であること**。背景も効果も、相手の立場から書く。

## 目次
1. 必須7要素と雛形の対応
2. 社外向け（クライアント営業）の標準構成
3. 社内向け（稟議・改善提案）の標準構成
4. セクション別ヒアリングガイド

---

## 1. 必須7要素と雛形の対応
| 必須要素 | 使うスライド（type） |
|---|---|
| 1. タイトル（表紙） | cover（`to` に宛先、`company` に自社名） |
| 2. 背景・現状分析（課題の共有） | current_issues（必要に応じて asis_tobe・background も） |
| 3. 提案の結論・概要 | summary（section を「提案の概要」にする） |
| 4. 具体的な提案内容（解決策） | solution（手順があれば process も） |
| 5. メリット・期待される効果 | benefits |
| 6. スケジュール・体制・費用 | schedule ＋ options（プラン比較）または budget（費用内訳・投資対効果） |
| 7. 結論・まとめ（会社概要・実績） | next_action（`conclusion` に総括）＋ company（社外向け） |

7要素はすべて入れる。1つでも欠けると、相手は判断できない。

## 2. 社外向け（クライアント営業）の標準構成
相手はまだこちらを信頼していない。**課題に共感してから**解決策を出す。

| # | type | section | 役割 |
|---|---|---|---|
| 表紙 | cover | — | 「〇〇株式会社 御中」、具体的な提案名、自社名・担当者・日付 |
| 目次 | agenda | — | 本日の流れ。各セクションをアイコン付きで並べ、話の道筋を先に見せる |
| 01 | current_issues | 背景・現状の課題 | ヒアリングで聞いた相手の課題を、相手の言葉と数字で示す |
| 02 | summary | ご提案の概要 | 何をどう解決するかの要点（課題・提案・効果）＋重要な数字 |
| 03 | solution | ご提案内容 | 課題ごとの解決策。各解決策に、対応する課題を書く |
| 04 | process | 導入ステップ | 導入の手順と期間。相手の負担が少ないことを示す |
| 05 | benefits | 期待される効果 | 導入前と導入後の変化を数字で示す。試算の根拠を出典に書く |
| 06 | options | プラン・費用 | 2〜3プランの比較（推奨を中央に）。税別・税込、初期費用、見積の有効期限 |
| 07 | schedule | スケジュール・体制 | 工程表と、両社の役割分担 |
| 08 | company | 会社概要・実績 | 信頼の裏付け。類似業種での導入事例 |
| 09 | next_action | まとめ・ネクストアクション | 結論（conclusion）を再度示し、次の打ち合わせやトライアルを促す |

- 相手が課題をすでに強く認識している場合や、役員向けで結論を急ぐ場合は、02 の概要を 01 より前に置いてもよい
- 費用を1案で出す場合は options の代わりに budget を使う

## 3. 社内向け（稟議・改善提案）の標準構成
読み手は忙しい決裁者。**結論を先に**出し、判断に必要な材料（費用対効果・リスク・代替案）をそろえる。

| # | type | section | 役割 |
|---|---|---|---|
| 表紙 | cover | — | 宛先（例：「管理本部長 殿」）、提案名、部署・氏名・日付、社外秘 |
| 目次 | agenda | — | 説明の順番（結論 → 根拠 → 費用 → リスク）を先に見せる。8枚以下なら省いてよい |
| 01 | summary | 提案の概要 | 何を承認してほしいか、費用、効果を1枚で示す |
| 02 | current_issues | 背景・現状の課題 | 社内データで示す課題と、放置した場合の損失 |
| 03 | asis_tobe | As-Is / To-Be | 現状と目指す姿（任意。業務改善では入れると伝わりやすい） |
| 04 | solution | 提案内容 | 何をどう変えるか |
| 05 | benefits | 期待される効果 | 工数削減は「時間×人数×時給」で金額に換算する |
| 06 | budget | 費用・投資対効果 | 費目別の内訳、年度別の収支、ROI・回収期間、計上する費目 |
| 07 | options | 比較検討した案 | 現状維持・推奨案・別案を比較して、なぜこの案なのかを示す |
| 08 | schedule | スケジュール・体制 | 責任者は実名で書く |
| 09 | effect_risk | リスク・関連部署への影響 | 左に関連部署への影響と合意状況（`effects_label`）、右にリスクと対策 |
| 10 | next_action | 承認のお願い | 承認してほしい事項、金額、期限 |

## 4. セクション別ヒアリングガイド
最初に、宛先（社名・部署・役職）、提出日、自社名（社外向け）または部署名（社内向け）を確認する。

### current_issues（背景・現状の課題）
- 必須：相手の課題を2〜4個。それぞれに「何が起きているか（数字）」と「その影響」
- 推奨：このままにした場合の損失（insight）、データの出典（ヒアリング日、社内調査など）
- 社外向けの質問例：「ヒアリングで先方が一番困っていたことは何ですか？先方が使っていた言葉や数字はありますか？」
- 社内向けの質問例：「現状の課題を示す社内データ（作業時間、件数、コスト）はありますか？」
- チェック：課題が相手の視点で書かれているか。自社製品の宣伝になっていないか。

### summary（提案の概要）
- items：課題・提案・効果の3点（社外向けは「解決する課題／ご提案内容／得られる効果」、社内向けは「課題／提案／効果」）
- kpis：効果・費用・期間など、判断に効く数字を2〜3個
- 社内向けは message で「何を承認してほしいか」まで言い切る

### solution（提案内容）
- overview：提案の要点を1〜2文（任意）
- items：解決策を2〜4個。title、text、issue（どの課題に対応するか）
- 質問例：「この解決策は、どの課題に効きますか？」
- チェック：current_issues のすべての課題に、対応する解決策があるか。

### process（導入ステップ）
- steps：3〜5段階。title、period（期間）、text（やること）。山場（稼働開始など）は highlight
- チェック：相手側の作業・負担も書いてあるか（社外向け）。

### benefits（期待される効果）
- metrics：1〜3個。label、value（変化量）、before、after
- points：数字にしにくい効果
- sources：試算の前提（例：「時給2,400円×38時間×12か月」）
- チェック：試算の前提が相手の数字（ヒアリング・社内データ）に基づいているか。誇張していないか。

### options（プラン・費用 ／ 比較検討した案）
- plans：2〜3案。name、price、note、features、recommended（1つだけ）
- 社外向け：税別か税込か、初期費用、見積の有効期限を sources に必ず書く
- 社内向け：「現状維持」を1案に入れると、やらない場合との比較になる
- 推奨案を中央に置くと選ばれやすい（松竹梅の法則）

### budget（費用・投資対効果）
企画書と同じ（kikakusho.md の「予算・収支計画」を参照）。社内向けでは、計上する費目と決裁権限の金額ラインも確認する。

### schedule（スケジュール・体制）
企画書と同じ。社外向けは、相手側の担当（「貴社 管理部」など）も owner に書く。

### company（会社概要・実績）※社外向け
- profile：会社名、設立、所在地、従業員数、事業内容
- achievements：導入社数、継続率などの実績値（1〜3個）
- cases：類似事例（社名を出す場合は掲載の許可を確認）
- チェック：実績の数字は事実か。古い数字になっていないか。

### effect_risk（リスク・関連部署への影響）※社内向け
- effects_label を「関連部署への影響」にし、影響する部署・工数・合意状況を書く
- risks：リスクと対策を2〜4件

### next_action（まとめ・ネクストアクション）
- conclusion：提案の総括を1文（社外向けでは推奨）
- asks：相手にお願いすること＋期限
  - 社外向け：打ち合わせ、トライアル、見積依頼など、相手が動きやすい小さな一歩
  - 社内向け：承認事項と金額、人員・予算の確保
- contact：連絡先
